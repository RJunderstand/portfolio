01 / SORA

SEN Exam Support Tool

The tool checks the registers for me, and no student data leaves the device.

24 min → 30 sec

by hand, uninterrupted → with the tool

same task, to scale · 28 groups

Excel VLOOKUP Local web tool On-device WCAG 2.2 AA UK GDPR axe-core · 0 violations

Scale: 15 modules · 28 exam groups · 4 to 80 students in each group, about 1,000 students. I checked them by hand under exam-season deadlines.

Plus: I consolidated the termly lecturer-notify workflow into one master sheet. It went from 3 days to 1 day, 155 emails with near-zero errors.

Problem

For every exam, someone has to check two separate registers against each other. I did it by hand: downloading the per-subject lists, checking them against the master disability support list, then chasing missing medical evidence. It was slow, it was easy to get wrong, and it handled special category data.

Constraint

The files hold special category disability data, covered by UK GDPR and the DPA 2018. There was no budget. Three rules set the compliance line: the Equality Act 2010, the Public Sector Bodies Accessibility Regulations 2018 (PSBAR), and WCAG 2.2 AA.

Scale

15 modules, 28 exam groups, between 4 and 80 students in each group, about 1,000 students in total. I checked them by hand under exam-season deadlines. If I get one wrong, that is a data breach.

What I built · the learning curve

It started as a two-day manual job. I got fluent with Excel formulas and cut it to two hours. Then I asked what AI could add, and rebuilt it as a local tool that runs in the browser. It reads the files and produces the adjustment list on its own. The browser reads the files on my own machine. Nothing is uploaded, nothing is changed, and the list clears when I refresh the page. It meets the Equality Act 2010 and PSBAR / WCAG 2.2 AA.

The tool matches students by enrolment ID, so it skips the hand-typed register. That is the step most likely to go wrong. It then checks back in the other direction. It flags problems and never edits the file, and every flag goes to a person.

What this transfers

Other teams have the same problem: two lists that have to match. Anyone can run the check on their own files and get the same answer every time, and the tool also reports on the data quality of both registers. In an institution with a central records system, the same approach fits the exam and reasonable-adjustment processes already in place. Only the data source changes.

What I had to fix

Three things needed fixing. SoRA is special category data, so files are read in the browser and nothing is uploaded. One component had a known vulnerability, so I replaced it with a patched build. I now re-check the components each term, because a tool that people use has to be checked again. I had never tested my own accessibility, so I tested it with axe-core 4.13.0: 27 passes, 0 violations. That covers automated, machine-testable rules only, so it is not a conformance claim. The first real run also found 2 adjustment records that did not link back at all.

Status: it has one user so far, and that is me. Nobody else has tried it yet.

04 / Accessibility

Document Accessibility Pilot

Students understood the words. The documents were built wrong.

0 of 4

student-facing documents passed the checker

PAC audit PDF/UA (ISO 14289-1) SCULPT extended Equality Act 2010 PSBAR 2018
Structural errors · before15,000+
After rebuilding~30

9-point checklist: SCULPT extended from six after testing exposed two gaps.

Problem

Students kept asking about things the material already answered. At the front desk we answered the same questions one student at a time. In class, trainers used teaching time to explain points the document was supposed to carry. Every one of those questions was a student spending time on the document instead of on the course. The documents looked tidy. Nobody had measured them.

Constraint

Three things I could not change. Free tools only, so I used PAC, which runs offline, and the measurement never left my laptop. There was no route to ask for a data-protection review, so I used published material only and no student records. And there is no route for me to publish the fixed version. I can measure a document and I can fix it. Someone else has to publish it.

What I built

I tested four documents with PAC (axes4) against PDF/UA (ISO 14289-1) and the machine-checkable WCAG 2.1 criteria. None of them passed, and one file had over 15,000 structural errors. I rebuilt that file and re-tested it: about 30 errors, a 99.8% drop. The rebuild changed five things. Language: short sentences, active voice. Structure: clear headings, numbered steps. Readability: bold key terms and spacing that does not crowd the page. Connective logic: signposting that helps readers with ADHD and dyslexia follow the thread. Alt text: a description for every diagram and image. I worked in my work account only, inside the Microsoft 365 boundary and under enterprise data protection. AI helped me rebuild the file. The check is a rules engine, not AI, so anyone can re-run it and get the same answer, and I read every change myself. Testing also exposed two gaps in the SCULPT framework, so I extended it into a nine-point checklist.

What this transfers

The regulations already cover the VLE, and the Equality Act duty is anticipatory. It does not wait for a student to ask. Build accessibility in from the start rather than adding it afterwards, and measure the real baseline before trusting any checklist.

Honest limits: the finding is that 0 of 4 passed. The 99.8% drop only shows that one file can be fixed. This is a pilot on one document and it has not gone to students. Automated checks are not a conformance claim, and I have not measured whether enquiries went down.

06 / Signposting

Find Support in Manchester

24

organisations, each verified by hand

AI-built Signposting Open source

Students came to us for stress and anxiety (44%), finance, family and relationships (33%), studies (8%), and health or sleep (6%). Some of what they need sits outside the campus, and not every student tells us on their own. UCAS found in 2021 that 49% of first-year students had not told their university about a mental health condition. So I asked whether this could work without anyone having to disclose anything. Nobody should have to claim a label just to get a list of links. There is no form, no account and no record, and 999 is on every screen.

I built a tracker for every organisation and contacted all of them. I approached 26 local organisations, and took 6 of them further this year with a meeting and then a visit. I made a paper handout students could take away, and then built the web version.

I checked it in three ways. Technical: 41 automated checks, 38 passed and 3 failed, and I fixed the 3. Content: I checked all 24 organisations one by one against the Charity Commission register. 21 were confirmed on the register. 3 had no registration, and one was trading under a new name. I corrected or removed those and added an annual re-check. All 24 rows were signed off on 6 August 2026. Inclusion: no form, no account, no record.

Status: we made the printed guide with the team and Marketing. It is approved and scheduled for every new student's Welcome Bag in September 2026. The online route is built. Nobody is using it yet. Print numbers sit with Marketing.

Transfers as: an open-source signposting pattern that any student services team can copy and adapt to their own area.

07 / How I stay current

No-Code Sector Intelligence Pipeline

The workflow does the routine steps. I still make the judgement calls.

£0

to run · no-code

reading week · 3–4 hrs → ~30 min

Make.com Notion No-code v1 free tier v2 structured JSON

Presenting at TIRIAE 2026 · UGM Bolton campus · 3 September · Paper 116 · 7-minute lightning talk and A1 poster

What I learned

Professional services staff in higher education are expected to keep up with a sector that changes fast. In a full-time role there is rarely time to gather, filter and use that information without taking it out of life outside work. That leaves a practical gap: a way to stay current that takes little effort and needs no technical background.

Rationale. I chose an AI-assisted, no-code route because the alternatives ask too much. Conventional automation and custom development need technical skill, cost time and money to maintain, and stay limited without programming. I found that out myself using standard automation tools. No-code platforms with AI support lower the barrier enough that staff without a technical background can build something that works.

Methodology and approach. The design logic matters more than the software. I described the problem to an AI assistant in plain language, like a product brief: who would use it, what they needed, and what it had to do. The assistant offered several options. I picked the one that suited my background and my constraints, then built it step by step, using screenshots whenever an instruction was unclear. Evaluating, choosing and building this way produced one connected workflow. It collects sector updates, summarises them with a large language model, filters the results, and files them in one place I can search. The stages run automatically, one after the other. I set it up in about half a day, with no technical training and an arts background, using no-code tools anyone can get. It has run without my help since.

Results and findings. Following the sector used to be scattered and slow. Now it is a short routine, and I can read the output at any time on my work computer, my own laptop or my phone. Using it showed me one clear strength and one clear limit of AI. The strength is understanding and recommending: it draws on a wide range of tools and options, and closes gaps I could not close on my own. The limit is step-by-step guidance. That help is still text, so I still have to work out which written instruction means which action on screen.

Conclusions and implications. The model matters more than the tool. This is a low-cost approach that colleagues without a technical background can repeat by following the same steps. I am also looking at a more structured, searchable version, because filtering and finding information gets harder as the volume grows. Working with machines this way should let people use more of their own creativity, not take their work away.

Limitations, in three tiers

Technical, now fixed. I moved the relevance filter earlier in the chain.

Structural. The platform cost nothing, but someone still had to know how to build it.

Epistemic. I only see what my own search terms find, and only what people publish openly. If something is missing, nothing tells me it is missing.
